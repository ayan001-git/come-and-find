# Come and Find — обновлённый учебный проект (04.11.2026)

Это полная версия проекта на Go + PostgreSQL + HTML/CSS/JavaScript, созданная на основе предоставленного `Come_and_Find_Voice_Fix.zip`. Сохранены основные API и роли Buyer / Supplier / Admin. Данные в существующем Docker volume не удаляются при обычной пересборке.

## Что улучшено

### Интерфейс
- Компактная шапка с логотипом и названием вместо слишком крупного изображения.
- Переработанная главная страница, карточки товаров, фильтры, каталог и модальные окна.
- Адаптивность под экран телефона (проверена в Chromium с имитацией API на 390 px).
- Изображения демонстрационных товаров выбираются по категориям, если в старой базе указан общий `product.svg`.
- Цены показываются в формате `7 990 ₸`; есть кнопка «Show more products».
- Пустые результаты поиска имеют понятное сообщение и кнопку сброса.
- Вход без предзаполненного пароля; есть кнопки быстрого заполнения **демо-аккаунтов** для локальной защиты.
- Голосовой ввод показывает состояние и после распознавания инициирует поиск, оставляя текст редактируемым.
- Улучшены подписи, сообщения и доступность клавиатурой.

### Backend и инфраструктура
- Новый `GET /api/health`: проверяет доступность PostgreSQL (200 OK или 503).
- Ограничения времени чтения/записи HTTP и размер заголовков.
- Дополнительные HTTP-заголовки `X-Frame-Options`, `Permissions-Policy`.
- JSON с неизвестными полями отклоняется; регистрация требует точный email без display name.
- Дополнительные лимиты на название, описание, изображение и количество характеристик товара.
- PostgreSQL доступен на хосте только через `127.0.0.1:5433`; внутри Docker по-прежнему используется `db:5432`.
- Healthcheck приложения в Compose, новые Go-тесты для JSON и HTTP-заголовков.

## Как запустить в VS Code (Windows)

1. **Сохраните резервную копию** старой папки `come-and-find`.
2. Распакуйте архив в отдельную папку (внутри архива файлы лежат в `come-and-find/`).
3. Откройте папку `come-and-find` в VS Code.
4. Убедитесь, что Docker Desktop запущен.
5. В терминале VS Code:

```powershell
docker compose up --build -d
docker compose ps
```

6. Откройте **http://localhost:8080**. Для проверки backend откройте **http://localhost:8080/api/health**.
7. Если Chrome показывает старую версию, нажмите `Ctrl + Shift + R`.
8. Для логов: `docker compose logs -f app`. Для остановки: `docker compose down`.

**Не запускайте `docker compose down -v`, если хотите сохранить базу данных.**

### Демо-аккаунты (только для локального учебного использования)

- Buyer: `buyer@example.kz` / `Buyer123!`
- Supplier: `supplier@techline.kz` / `Supplier123!`
- Admin: `admin@comeandfind.kz` / `Admin123!`

В окне входа нажмите соответствующую кнопку роли, чтобы заполнить поля, затем нажмите **Sign in**.

## Проверка

- `node --check web/app.js` — выполнена успешно.
- `node --check web/voice.js` — выполнена успешно.
- Chromium (с имитацией API): страницы на 1440 px и 390 px, 9 карточек, кнопка быстрого демо-входа, без JavaScript-ошибок и горизонтального переполнения.
- 7 сценариев голосового ввода с имитацией `SpeechRecognition` — успешно (на основе тестового набора из предыдущего патча).
- `gofmt` — выполнен для изменённых Go-файлов.
- `go test ./...` в среде подготовки **не завершился**: отсутствуют локально кэшированные Go-модули и сеть для их загрузки. Docker у пользователя ранее успешно собрал исходную версию, но **обновлённый Go-код и PostgreSQL ещё нужно проверить на его Windows**.

## Ограничения

- Голосовое распознавание зависит от браузера, разрешения микрофона, поддержки языка и сетевого сервиса. Казахский язык может не поддерживаться браузером.
- Платежи имитируются. Нет реальных транзакций, доставки, уведомлений и внешних платёжных систем.
- Это учебный MVP, **не готовый production-сервис**. Демо-пароли и конфигурацию PostgreSQL нельзя использовать в публичном интернете.
- Внешние фото товаров не подключены; для каталога используются локальные иллюстрации.
- Изменение CSS/JavaScript не удаляет ваши записи в базе. Однако изменение конфигурации контейнеров и тесты на существующей базе требуют резервной копии.

## Тесты после запуска Docker

```powershell
docker compose ps
docker compose logs --tail=100 app
```

В браузере: войти как Buyer → добавить товар → открыть корзину → создать заказ → имитировать оплату → войти как Supplier → обработать заказ → войти как Admin → проверить модерацию. Голос проверить в Chrome на `localhost`.

Автоматический `tests/api_regression.py` **изменяет данные**, поэтому запускайте его только на отдельной тестовой базе, не на вашей текущей рабочей базе.
