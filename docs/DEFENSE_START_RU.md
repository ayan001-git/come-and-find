# С чего начать защиту TSIS 4-7

Проект Come and Find соединяет покупателей и поставщиков компьютерных аксессуаров.
Покупатель находит товар, проверяет данные и оформляет заказ. Поставщик получает
заказ; администратор проверяет публикации. Платежи демонстрационные.

TSIS 4: какие навыки нужны и чего не хватает. Новое: Speech API/умный поиск.
Объясни, что текущие уровни - самооценка, а обучение и помощь уменьшают риски.

TSIS 5: зачем делаем, какие цели, границы, сроки, ресурсы и риски.
Цели проверяются конкретными сценариями. Голосовой ввод теперь Must;
совместимость браузера - риск, текстовый ввод - резервный вариант.

TSIS 6: потребность пользователя и проверяемый результат Given/When/Then.
US-04: покупатель диктует запрос, проверяет текст и получает подходящие товары.
Негативный сценарий: нет разрешения - сообщение и доступный ввод с клавиатуры.
Прогноз ценности - условная оценка экономии времени, а не реальная выручка.

TSIS 7: порядок историй, относительные SP, релизы, бюджет и задачи спринта.
SP не равны часам. После изменения US-04: 38 SP Must, 44 SP всего.
Сроки и суммы - плановые оценки. Пример голосов poker не является реальным протоколом.

В backend обязательно объясни: сессия и роль; цены из БД; транзакция заказа;
проверка остатка; один поставщик; допустимые переходы статуса.

После короткого объяснения документов показывай сайт, если преподаватель просит.
Начни с голосового поиска, затем карточка -> корзина -> заказ -> оплата-симуляция
-> поставщик -> одобрение нового товара администратором.

Подробности новой функции: VOICE_SEARCH_RU.md. Актуальные отчёты находятся в EN и RU.
